# Idaho conditions: reviewed refresh

The refresh downloads public source candidates, builds isolated map and filter artifacts, checks the result, and applies a digest-verified plan to the feature branch. It does not connect to the production database, run agency synchronization, or enable a schedule.

1. Start from the published main branch on a feature branch. Keep the previously reviewed `out/id-terrain`, `out/id-fire`, `out/id-conditions`, and `out/geodeps` caches available. These include the 100-m elevation and route grids, historic NIFC inventories, agency sites, historic drought snapshots, and snow-station history. The build checks the published historical source hashes and stops if a cache is missing or changed. These working caches are not tracked in Git; retain them and the terrain grids outside the checkout for subsequent refreshes. The cache created at `out/id-refresh-builds/<dates>/out/id-fire` and `.../out/id-conditions` is the input baseline for the following refresh. Set `ID_FIRE_CACHE` and `ID_CONDITIONS_CACHE` to those paths when running the next build. `ID_BUILD_SUFFIX` can create a separate repeat build without overwriting an existing review.
2. Run `node scripts/id-conditions-stage.cjs YYYY-MM-DD YYYY-MM-DD`, providing the requested as-of date and the actual USDM Tuesday. It creates a new candidate directory, downloads the weekly drought polygons, recent NRCS station readings and current-year NIFC perimeter geometry, checks inventories and records exact URLs, download time, counts and SHA-256 hashes. After April 1 or the last September Tuesday in a later year it also stages that year's historical observation where applicable. The current-year NIFC inventory is as downloaded; its discovery-year query is not a reconstruction of what was known on the as-of date. Inspect missing, anomalous or revised data and official source notices. The directory cannot be overwritten.
3. Run `node scripts/id-conditions-refresh.cjs <candidate-directory> <python-executable>`. It verifies source hashes and inventories, creates a separate build directory, rebuilds all 100 unit conditions, fire summaries, terrain/fire overlap masks, visual overlays and the statewide drought overlay, then checks old history, unit identities and drought geometry against unit percentages. It writes `review-plan.json` containing all output and original-target hashes. No published artifact is touched. A cache, Python geospatial packages, adequate free space, and network access for any unrepairable source geometry are required. The route, land and access-site layers retain their original 2026 vintages; refreshing snow, drought and fire does not refresh those inputs.
4. Review source dates and hashes, source record counts, representative unit changes, fire perimeter provenance, station readings, map/category coverage and the validation report. Check for new source reporting issues, stale datasets and implausible changes. Verify dated labels, overlap filters, charts, statewide map, desktop and mobile. Compute the SHA-256 of `review-plan.json`; `node scripts/id-conditions-apply.cjs <build-directory> <plan-sha256>` checks every generated hash and every existing target hash before copying the reviewed artifacts. It refuses unexpected paths or a changed plan. Review the resulting git diff.
5. Run the full tests, typecheck, production build and user-journey checks. Update documentation to identify the published dates and differences, merge/deploy, and verify the live unit and statewide maps and health. Do not change a date label alone, call a snapshot live, replace missing measurements with zero, or run destructive schema commands. The NOAA snow model is a separate live service; its displayed valid time comes from NOAA.

The rolling fire mask covers the previous eight years in its year-specific bits, plus an all-period flag; aging ranges and labels move with the published fire snapshot. Annual source gaps or absent historical caches must be resolved and validated before a later-year refresh. The USDM layer remains restricted to Idaho game units. A refresh of these visual assets does not update route or agency access-site inventories.
