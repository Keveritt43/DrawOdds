# Access, filters and Colorado pages

- New visitors default to antlered. Explicit antlerless, both, and Any selections persist. Either-sex hunts match either class and retain their either-sex label.
- Signed-in filters live in existing User.points JSON under reserved _filters_ID/_filters_CO keys; visitors use state-specific one-year cookies. Atomic jsonb_set writes preserve points, plans and other states. The point writer also updates atomically. No schema changes. Account plans for Colorado use _plan_CO, separate from the existing Idaho plan. Browser filter saves are serialized.
- Returning to the finder restores each state's query before rendering. Reset returns to antlered. Export uses the same eligible-season predicate as Idaho results.
- Date and month matching uses regulation spans filtered for youth visibility and method, rather than the combined adult/youth closing date. Including youth preserves a tag that is still open only to youth; hiding youth removes that extension from matching. Exact season gaps remain gaps.
- Recommendations are closed details titled Recommended Tags. Idaho trophy ranking sorts controlled antlered/either hunts by verified scoreTrophy, breaking ties by combined resident/nonresident applicants. Colorado displays its lack of verified trophy measurements explicitly instead of inventing a trophy score.
- Method follows License Type. Idaho Season Dates and Deer Type are promoted above More Filters. Both states use Antlered/Antlerless; Colorado adds date, youth and public-land controls.
- data/co-land.json covers all 186 CPW GMUs. scripts/build-co-land.py caches the official BLM SMA source and CPW GMUs, projects through the source service to EPSG:5070, intersects and unions ownership classes, and rejects incomplete coverage or excessive overlaps. Python dependencies: requests and shapely (offline authoring only). The script never connects to a database. Public/private/tribal/unmapped shares remain separate. Ownership never implies permission. No private-access-program acreage is added to Colorado.
- Ownership percentages and revised area-based density are overlaid when Colorado pages/API responses are read; no stored historical rows are rewritten. All CO cards, hunt/unit pages and maps use this artifact. Colorado omits Access Yes! controls. Access-program names come from state configuration so BMA can be configured for a future Montana implementation.
- Hunt details show code-specific survey counts with full covered-unit labels plus the latest broader unit/weapon/season estimates. Statewide OTC hunter counts are never represented as single-unit counts. Overlapping elk rows add average annual hunters and hunters/mi², labeled for their full hunt coverage.
- Colorado has state-specific home, map, finder, unit/hunt pages, guide, methods, changes, score explanation and account-backed planner. The map loads Colorado geometry/bounds, prefixes unit API/detail links correctly, and uses CPW attribution. Quality/trophy scores remain unvalidated for Colorado, distinct from now-available ownership.

No agency synchronization, schema command, historical-data rewrite, or production deployment is part of preparing this change. The explicit Colorado land-source fetch is an offline artifact build. Automatic sync stays disabled.
